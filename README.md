# КазнаЛинза — система скоринга заявителей на агросубсидии

**Хакатон:** Decentrathon 5.0 · **Кейс:** №2 — автоматизированный скоринг заявителей на сельскохозяйственные субсидии (Казахстан)

---

## О проекте

**КазнаЛинза** — аналитическая GovTech-система для Министерства сельского хозяйства Республики Казахстан. Система анализирует историю заявок на агросубсидии, строит merit-based рейтинг заявителей, сегментирует их по поведенческим паттернам и выявляет подозрительную активность — в едином веб-интерфейсе для государственных служащих.

Система **не принимает решения за чиновника** — она помогает принять обоснованное решение быстрее и точнее.

---

## Ключевые возможности

- **Рейтинг заявителей** — композитный индекс на основе пяти факторов: доля одобренных заявок, объём субсидий, активность, диверсификация, актуальность.
- **ИИ-скоринг** — модель LightGBM с калибровкой; в интерфейсе отображается **индекс надёжности** в шкале **0–100**.
- **Сегментация** — кластеризация K-Means: *Крупные эффективные*, *Средние стабильные*, *Малые активные*, *Малые рискованные*.
- **Детекция аномалий** — Isolation Forest; в интерфейсе — **уровни риска**: высокий, средний, повышенное внимание (без вывода сырых технических метрик конечному пользователю).
- **AI-Аналитик** — чат на Groq (Llama 3.3 70B), ответы по данным простым языком, без излишнего технического жаргона.
- **Фильтры** — по региону и типу субсидии; применяются ко всем основным разделам дашборда.

## Быстрый старт

### 1. Установка зависимостей

```bash
pip install -r requirements.txt
```

Рекомендуется выполнять команды из **корня репозитория**, чтобы пути к `data/` и приложению были корректны.

### 2. Данные

Поместите исходный файл Excel в каталог `data/raw/`. При необходимости укажите путь к файлу в `src/preprocessing.py` (переменная пути к сырым данным).

> После клонирования репозитория сгенерированные CSV и артефакты моделей могут отсутствовать (часто перечислены в `.gitignore`). Пока не выполнены шаги пайплайна, API может отдавать пустые или неполные данные — это ожидаемо.

### 3. Пайплайн

```bash
python src/preprocessing.py
python src/ml_model.py
```

### 4. Запуск веб-интерфейса

```bash
python app/server.py
```

Откройте в браузере: **http://localhost:8502**

### 5. AI-Аналитик (опционально)

Создайте в корне проекта файл `.env`:

```env
GROQ_API_KEY=ваш_ключ
```

Шаблон см. в `.env.example`.

```
data/raw/*.xlsx
  → src/preprocessing.py → data/processed/features.csv
  → src/scoring.py       → composite score, rank
  → src/ml_model.py      → K-Means, Isolation Forest, LightGBM
  → data/processed/ml_results.csv
  → app/server.py        → REST API → app/index.html
```

## REST API

Сервер `app/server.py` отдаёт статику и JSON API для фронтенда:

| Эндпоинт | Описание |
|----------|----------|
| `GET /api/all` | Все заявители с индексами и признаками |
| `GET /api/explain/{id}` | Разложение композитного индекса по факторам |
| `GET /api/applicant/{id}` | Профиль заявителя |
| `POST /api/chat` | AI-аналитик (Groq) |

Дополнительно может быть доступен `GET /api/debug` для отладки загрузки данных.

## Честный чеклист

- **Индекс надёжности** — вспомогательный сигнал для приоритизации, **не замена** юридическому или процедурному решению.
- **ML-вероятность после калибровки** — это не «вероятность одобрения следующей заявки», а **оценка модели** по выбранной в обучении постановке задачи; трактуйте её как один из сигналов наряду с композитом и экспертизой.
- Система предназначена для **аналитики и приоритизации**; итоговое решение принимает **специалист**.
