# 🌾 Subsidy Scoring System — Система скоринга сельхозпроизводителей Казахстана

> **Хакатон:** Decentrathon 5.0 | **Кейс:** №2 — Скоринг при подаче на субсидии

---

## 📋 Описание задачи

**Кейс 2: Автоматизированный скоринг заявителей на получение сельскохозяйственных субсидий**

Разработка ML-системы, которая оценивает сельхозпроизводителей Казахстана по совокупности показателей и формирует **merit-based** рейтинг заявителей для справедливого распределения государственных субсидий.

---

## 🚨 Проблема

Текущая система распределения субсидий работает по принципу:

> **"Первый подал — первый получил"**

Это приводит к следующим последствиям:
- ✗ Субсидии достаются тем, кто быстрее подал документы, а не тем, кто эффективнее ведёт хозяйство
- ✗ Недобросовестные заявители могут получать финансирование в обход реально нуждающихся производителей
- ✗ Отсутствие анализа исторических данных об эффективности хозяйств
- ✗ Непрозрачность критериев отбора
- ✗ Невозможность выявить системные злоупотребления

---

## ✅ Решение

Автоматизированная система скоринга на основе машинного обучения, анализирующая **36 651 заявку** от **457 уникальных заявителей** и формирующая объективный рейтинг по совокупности значимых признаков.

### Принципы системы:
- 📊 **Merit-based подход** — оценка по реальным показателям эффективности
- 🔍 **Прозрачность** — объяснимость решений через SHAP-values
- ⚖️ **Справедливость** — одинаковые правила для всех заявителей
- 🤖 **Автоматизация** — минимизация человеческого фактора

## 🚀 Как запустить

### 1. Клонирование репозитория

```bash
git clone https://github.com/your-org/subsidy-scoring-system.git
cd subsidy-scoring-system
```

### 2. Установка зависимостей

```bash
pip install -r requirements.txt
```

### 3. Запуск демо

```bash
python demo.py
```

### 4. Запуск API-сервера

```bash
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

Документация API будет доступна по адресу: `http://localhost:8000/docs`

### 5. (Опционально) Полный пайплайн обучения

```bash
python src/preprocessing.py   # Предобработка данных
python src/feature_engineering.py  # Генерация признаков
python src/model.py           # Обучение модели
python src/scoring.py         # Расчёт скоров
```

## 📂 Структура данных и признаки

### Источник данных

- **Всего заявок:** 36 651
- **Уникальных заявителей:** 457
- **Формат:** Microsoft Excel (.xlsx)

### Ключевые признаки (Features)

#### 📌 Идентификационные данные
| Признак | Описание |
|---------|----------|
| `applicant_id` | Уникальный идентификатор заявителя (ИИН/БИН) |
| `region` | Регион / область Казахстана |
| `application_date` | Дата подачи заявки |

#### 📈 Производственные показатели
| Признак | Описание |
|---------|----------|
| `land_area_ha` | Площадь земельных угодий (га) |
| `crop_type` | Тип возделываемой культуры |
| `yield_per_ha` | Урожайность (ц/га) |
| `livestock_count` | Поголовье скота |

#### 💰 Финансовые показатели
| Признак | Описание |
|---------|----------|
| `subsidy_amount_requested` | Запрашиваемая сумма субсидии (тг) |
| `previous_subsidy_received` | Получено субсидий ранее (тг) |
| `revenue` | Выручка от с/х деятельности (тг) |

#### 🏆 Исторические показатели
| Признак | Описание |
|---------|----------|
| `application_count` | Количество ранее поданных заявок |
| `approval_rate` | Доля одобренных заявок |
| `compliance_score` | Оценка соблюдения условий предыдущих субсидий |

#### 📊 Сгенерированные признаки (Feature Engineering)
| Признак | Формула |
|---------|---------|
| `efficiency_score` | `revenue / land_area_ha` |
| `subsidy_utilization_rate` | `previous_subsidy_received / subsidy_amount_requested` |
| `application_frequency` | Число заявок за последние 12 месяцев |

## ⚠️ Ограничения модели

1. **Качество входных данных** — модель чувствительна к пропускам и ошибкам в исходных данных; рекомендуется предварительная валидация
2. **Временной дрейф** — признаки, актуальные сегодня, могут потерять предиктивную силу через 1–2 года без переобучения модели
3. **Географическая специфика** — модель обучена на казахстанских данных и не предназначена для прямого переноса на другие страны
4. **Класс дисбаланса** — при малом числе одобрений в отдельных регионах возможна пониженная точность для этих групп
5. **Интерпретируемость** — SHAP-объяснения дают приближения важности признаков, а не юридически обязывающие обоснования решений
6. **Не заменяет экспертизу** — система является инструментом поддержки принятия решений, окончательное решение остаётся за уполномоченным органом
